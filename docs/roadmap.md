# 后续优化路线

这份路线图用于说明项目后续维护方向。原则是先稳定、再拆分、最后扩展能力。

## 短期：结果解释和实验支撑

- 完善评分解释，让用户知道总分、动作分、节奏分和可信度分别代表什么。
- 补充终期论文测试样例，包括变速、起始错位、低质量输入等场景。
- 增加阶段级日志，尽量区分姿态提取、对齐评分和报告生成耗时。
- 继续维护轻量验证脚本，保证 issue index、AI fallback 和 Records Workspace 可检查。

## 中期：前端和核心模块拆分

- 拆分 `RecordsPage.vue`，优先抽出评分说明、AI 助教、记录详情和问题片段列表。
- 抽取 records 相关 composables，减少页面组件直接承担数据编排。
- 继续拆分 `core/pipeline.py`，保持 `features`、`scoring`、`issue_detection` 等边界清晰。
- 补充 pytest 或轻量后端测试，覆盖报告摘要、问题片段抽取、删除记录和 fallback 场景。

## 长期：训练档案和评价对照

- 建立训练档案，记录同一学员多次练习结果。
- 增加进步趋势，展示分数、问题片段和可信度的长期变化。
- 补充更多舞种、更多拍摄环境和更多学习者样例。
- 引入人工评分对照，用教师评价验证系统评分趋势。
- 在数据规模扩大后，将更多索引从文件迁移到数据库。
