# 中期答辩演示指南

这份指南用于答辩前排练和现场演示。目标不是展示所有菜单，而是稳定讲清楚系统闭环：视频输入、动作分析、问题片段复盘、训练建议生成。

## 演示前准备

- 准备一组教师示范视频和一组学员练习视频，时长尽量控制在 10-30 秒。
- 提前跑完至少一条分析记录，确保记录页有可展示的评分、可信度和问题片段。
- 检查 `run-desktop.bat` 能启动，系统设置页显示本地服务在线。
- 确认 `models/pose_landmarker_full.task` 存在，命令行可执行 `ffmpeg`。
- 如果要展示 AI 助教，提前确认 API Key 可用；没有 Key 时也可以展示本地规则兜底。

## 推荐演示路线

1. 素材库：展示教师视频和学员视频已经准备好。
2. 开始分析：选择一组素材，说明系统会完成姿态提取、DTW 对齐、评分和报告生成。
3. 分析记录：展示已完成记录的总分、可信度、问题片段和输出文件。
4. 问题片段复盘：点击问题片段，跳回动作分析页对应时间点。
5. AI 助教解读：展示训练建议，并强调它是辅助解释结构化报告。
6. 系统设置：简短展示本地服务、存储占用和维护能力。

## 现场演示步骤

1. 打开 `run-desktop.bat`，等待桌面应用加载完成。
2. 进入素材库，确认教师和学员视频存在。
3. 进入开始分析，选择教师视频和学员视频。
4. 如果视频很短，可以现场发起分析；如果现场时间紧，直接切到分析记录展示已完成结果。
5. 在分析记录中展开一条完成记录，展示得分、可信度和问题片段。
6. 点击问题片段或“定位到动作分析”，展示对应时间点复盘。
7. 点击 AI 助教解读，展示训练建议和兜底提示。

## Pipeline 跑得慢时怎么办

答辩现场不要把长视频 pipeline 作为唯一演示路径。可以先说明“分析任务支持后台执行”，然后直接打开提前准备好的已完成记录。重点展示闭环结果，而不是等待计算过程。

推荐话术：

> 为避免现场等待，我提前准备了一条已完成分析记录。系统实际流程是一样的：上传视频后进入 pipeline，完成后生成报告、骨架视频、问题片段索引和训练建议。

## AI 助教边界说明

AI 助教只负责把结构化分析结果转化为更容易理解的训练建议。动作误差不是由 AI 判断的，而是由姿态估计、DTW 对齐、动作评分、节奏评分和可信度指标计算得到。

推荐话术：

> AI 在这里不是裁判，它是解释器。核心判断来自本地算法，AI 只把报告内容整理成更适合学生理解和练习的建议。

## Issue Index 优化说明

分析完成后，系统会在输出目录生成 `outputs/<pair_name>/issues.json`。分析记录页优先读取这个轻量索引，而不是每次重新解析完整 `report.json`，因此历史记录变多时页面更稳定。

旧记录如果没有 `issues.json`，系统会 fallback 读取 report 并补建索引，保证兼容已有数据。

## 演示失败应急方案

- 桌面启动失败：改用 `run-browser-debug.bat`，并查看日志。
- 后端端口占用：关闭残留 Python / uvicorn 进程后重启。
- 新分析跑太慢：跳到已完成记录继续演示。
- AI 不可用：展示本地兜底建议，并说明 AI 不是核心算法。
- 问题片段为空：换用提前准备的中等分记录，或说明当前记录没有识别到高优先级片段。
- 前端异常：刷新页面或重启桌面入口，必要时用浏览器调试模式打开。
