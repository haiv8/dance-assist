# 演示指南

这份文档用于答辩或项目演示。目标不是展示所有菜单，而是稳定讲清楚：视频输入、动作分析、问题片段复盘、训练建议生成。

## 演示前准备

- 准备一组教师示范视频和一组学员练习视频，建议控制在 10-30 秒。
- 提前跑完至少一条分析记录，确保有可展示的分数、可信度和问题片段。
- 确认 `run-desktop.bat` 能启动，系统设置页显示本地服务在线。
- 确认 `models/pose_landmarker_full.task` 存在，命令行可执行 `ffmpeg`。
- 如果展示 AI 助教，提前确认 API Key 可用；没有 Key 时也可以展示本地 fallback。

## 5 分钟演示路线

1. 系统目标：说明项目用于舞蹈学习复盘，帮助用户知道哪里有问题、如何回看、下一步怎么练。
2. 素材库：展示教师视频和学员视频的上传、管理和快速带入分析。
3. 开始分析：选择一组素材，说明系统会进行姿态提取、DTW 对齐、评分和报告生成。
4. 分析记录：展示已完成记录的总分、动作分、节奏分、可信度和问题片段。
5. 问题回放 / AI 助教：从问题片段跳回对应时间点，并展示训练建议。
6. 系统设置：简单展示本地服务、模型文件、磁盘空间和运行状态检查。

## 现场失败应急方案

- 桌面入口打不开：改用 `run-browser-debug.bat`，并查看日志。
- 后端端口占用：关闭残留 Python / uvicorn 进程后重启。
- 新任务跑得慢：直接打开提前准备好的已完成记录。
- AI 不可用：展示本地 fallback，并说明 AI 不是核心评分算法。
- 问题片段为空：换用中等分记录，或说明当前记录没有识别到高优先级片段。
- 前端异常：刷新页面或重启桌面入口，必要时使用浏览器调试模式。

## 如何解释评分

- 总分是训练复盘指标，不是教师主观打分。
- 动作分主要看身体姿态、关节位置和动作轨迹是否接近教师示范。
- 节奏分主要看动作推进速度和转场时机是否匹配。
- 可信度反映姿态跟踪和对齐是否稳定；可信度低时，应结合视频回看谨慎判断。
- 如果老师问“为什么分数低”，优先解释动作偏差、跟踪质量、对齐稳定性，而不是只看总分。

## 如何解释 AI 助教边界

AI 助教只负责把结构化分析报告整理成更容易理解的训练建议。动作误差不是由 AI 判断的，而是由姿态估计、DTW 对齐、动作评分、节奏评分和可信度指标计算得到。

推荐说法：

> AI 在这里不是裁判，而是解释器。核心判断来自本地算法，AI 只把报告内容整理成适合学生理解和练习的建议。

## 如何解释 issue index

分析完成后，系统会在输出目录生成 `issues.json`。分析记录页优先读取这个轻量索引，而不是每次重新解析完整 `report.json`，这样历史记录变多时页面更稳定。

旧记录如果没有 `issues.json`，系统会 fallback 读取 report 并补建索引，保证兼容已有数据。
